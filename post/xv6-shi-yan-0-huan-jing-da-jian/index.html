xv6实验[0]-环境搭建

2026-06-05 4 min read

xv6实验的官方网站为https://pdos.csail.mit.edu/6.S081/2021
启动命令详解

qemu-system-riscv64 -machine virt -bios none -kernel kernel/kernel -m 128M -smp 3 -nographic -drive file=fs.img,if=none,format=raw,id=x0 -device virtio-blk-device,drive=x0,bus=virtio-mmio-bus.0

qemu-system-riscv64: 告诉 QEMU 软件，我们要模拟的是 64 位 RISC-V 架构的 CPU。

-machine virt: 指定我们要模拟的主板模型。virt 是一个通用的、虚拟的 RISC-V 开发板，专门为操作系统开发设计，没有真实的物理外设，但包含了 CPU、内存、中断控制器等核心逻辑。

-bios none: 不使用任何 BIOS。因为 xv6 是一个教学内核，它非常“傲慢”，直接接管机器，不需要像电脑开机那样加载主板的 UEFI 或 BIOS。

-kernel kernel/kernel: 加载核心心脏。它告诉 QEMU 把 xv6 内核文件（那个编译出来的 ELF 文件）加载到 RISC-V 内存的固定位置，并让 CPU 从内核的第一行代码开始执行。

-m 128M: 配置内存。给这台虚拟计算机分配 128MB 的内存，这对于 xv6 来说已经非常宽裕了。

-smp 3: 配置 CPU 核心数。模拟一个 3 核 的处理器（SMP 指对称多处理器）。这意味着 xv6 必须处理多核并发、锁竞争等复杂的场景。

-nographic: 不需要图形界面。让所有的输出（串口输出）直接显示在当前的终端窗口里，而不是弹出一个新的图形窗口，这非常适合在 SSH 远程环境里调试。

-drive file=fs.img,if=none,format=raw,id=x0: 装载硬盘。将你的 fs.img 镜像文件挂载为硬盘。id=x0 给这块盘起个名字叫 x0。

-device virtio-blk-device,drive=x0,bus=virtio-mmio-bus.0: 连接硬盘总线。将上面起名为 x0 的硬盘，通过 virtio 总线连接到虚拟主板上。virtio 是一种极其高效的虚拟化设备标准，让内核能通过内存映射（MMIO）快速读写硬盘。

下面进行vscode调试环境搭建，参考博客
https://acmicpc.top/2024/02/08/MIT-6.S081-lab0-配环境/

在.vscode文件夹创建launch.json文件，输入如下内容，注意miDebuggerPath要和自己编译xv6的编译器一致

{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "debug xv6",
            "type": "cppdbg",
            "request": "launch",
            "program": "${workspaceFolder}/kernel/kernel",
            "args": [],
            "stopAtEntry": true,
            "cwd": "${workspaceFolder}",
            "miDebuggerServerAddress": "localhost:26000",
            "miDebuggerPath": "/home/xiao/riscv/bin/riscv64-unknown-elf-gdb",
            "environment": [],
            "externalConsole": false,
            "MIMode": "gdb",
            "setupCommands": [
                {
                    "description": "pretty printing",
                    "text": "-enable-pretty-printing",
                    "ignoreFailures": true
                }
            ],
            "logging": {
                // "engineLogging": true,
                // "programOutput": true,
            }
        }
    ]
}

在qemu输入make qemu-gdb CPUS=1，打开vscode，按下f5。发现程序停留在

如果要调试用户区域代码，比如ls，需要在调试终端输入 exec file ./user/_ls，然后在xv6终端窗口输入ls即可看到程序执行到设置断点处，如下图所示，在左边可以看到寄存器和变量的值。
