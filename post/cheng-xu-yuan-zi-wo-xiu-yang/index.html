32位机中一条汇编指令4字节 比如 mov r0, #100
1110 (高 4 位)：条件码（代表无条件执行 AL）。
0011101：操作码（告诉 CPU 这是一条 MOV 指令）。
0000：目标寄存器（告诉 CPU 存到 R0 里面）。
0000 0110 0100 (最后的 12 位)：这就真正留给“立即数”的空间！

可以通过修改数据的可执行条件运行机器码，一般如果一个高函数被高频调用，可以把他转化为机器码放在ram里面，而不是默认的flash，或者通过__attribute__这个关键字来放入，一般都用__attribute__关键字，因为用c转机器码很麻烦，不能调用全局变量和其他函数。

#include <stdio.h>
#include <sys/mman.h>

__attribute__((aligned(4096))) char codebuf[] = {
    0x48, 0xc7, 0xc0, 0x3c, 0x00, 0x00, 0x00, // mov $60, %rax
    0x48, 0x31, 0xff,                         // xor %rdi, %rdi
    0x0f, 0x05                                // syscall
};
int main()
{
    void (*f)() = (void *)codebuf;
    mprotect(codebuf, sizeof(codebuf), PROT_READ|PROT_WRITE|PROT_EXEC);    
    f();
    printf("I am alive!\n");
    return 0;
}

  1. .symtab（Symbol Table，符号表）
    存什么：存放所有符号（函数名、全局变量、静态变量）的定长元数据。
    它的本质是一个结构体数组（每个结构体 Elf64_Sym 固定占用 24 字节），里面记录：
    该符号属于哪个段（例如属于 .text、.data 还是 .bss）。
    符号的内存偏移地址 / 相对位置。
    符号的大小（比如 int arr[100] 的大小就是 400 字节）。
    符号的名字偏移量（一个整数，指向 .strtab 中该名字字符串的起始下标）。

  2. .strtab（String Table，通用字符串表）
    存什么：存放函数名、变量名（符号名）的纯文本字符串。
    它就是一个以 \0 分隔的纯字符数组。比如 "main\0count\0global_buf\0"。
    symtab 中的结构体只需要存一个数字（例如偏移量 5），就能直接在 strtab 找到 "count" 这个名字。

  3. .shstrtab（Section Header String Table，节区名字字符串表）
    存什么：专门存放各个段自己的名字（Section Names）。
    它也是一个纯字符数组，存的是 ".text\0.data\0.bss\0.symtab\0.shstrtab\0" 等段名。

阶段一：函数调用与建栈（进入子函数）
第 1 步：从右向左压入形参（由 Caller / main 执行）push 20（参数 b）push 10（参数 a）esp 持续向下移动。
第 2 步：压入返回地址并跳转（由 call 指令硬件自动执行）将 call 下一行指令地址（图中的 0040109A）自动压入栈顶。将 CPU 的 PC 指针（EIP/RIP）修改为子函数入口地址，开始跳转。
第 3 步：保护旧栈底并立新栈底（标准序言 Prologue）push ebp：把上一层函数的栈底值（图中的 0x100）压入栈中备份。mov ebp, esp(函数参数)：将当前栈顶赋值给 ebp，作为新函数专属的基准零点（栈底）。
第 4 步：开辟局部变量空间与寄存器保护sub esp, 44h：栈顶继续向下移动，为局部变量 temp（[ebp-4]）预留空间。push ebx/esi/edi：备份被调用者保存寄存器，随后刷入 0xCC 缓冲区。阶段二：函数返回与销毁（退出子函数）
第 5 步：恢复寄存器并释放局部变量（esp 先回退）pop edi/esi/ebx：按相反顺序还原寄存器现场。mov esp, ebp：直接把栈顶拉回到 ebp 处，一瞬间销毁所有局部变量。
第 6 步：恢复旧栈底与跳转返回（ebp 回退 →\rightarrow→ 修改 PC）pop ebp：从栈顶弹出旧基址（0x100）送回 ebp 寄存器，ebp 瞬间恢复为 main 的栈底。ret：从栈顶弹出返回地址（0040109A）赋值给 PC 寄存器（EIP/RIP），硬件自动跳回 main 函数。add esp, 8（平栈）：main 函数将之前压入的两个参数（10 和 20）从栈中弹出丢弃，整个栈完全复原。具体如下

restrict 到底在保证什么？
它的本质是一个“契约”：你（程序员）向编译器做出法律声明一样保证——“在当前作用域内，访问该指针所指内存区域的唯一途径就是通过这个指针本身，绝没有任何其他指针会指向这块内存重叠的部分。”

全盘记账，但不动物理内存： execve 读取 ELF 头后，会一次性为所有需要加载的段（.text 代码段、.data 数据段等）建立好完整的 VMA 树。这一步仅仅是在内核空间登记了“哪段虚拟地址范围对应磁盘文件的哪个位置”，但实际上根本没有分配任何物理内存，也没有从磁盘读取任何代码数据。
直接放权，强制起跑： VMA 树建立完毕后，内核不做任何预加载，直接将 CPU 的 PC 指针强行设置到 ELF 记载的入口虚拟地址（通常位于 .text 段），并让 CPU 开始执行。
起跑即摔倒（首指缺页）： 因为物理内存中此时是空的，CPU 在尝试抓取第一条指令时就会立刻“踩空”，从而触发进程生命周期中的第一次缺页中断。
按需填坑： 内核捕获到这个中断，拿到入口的虚拟地址去查刚刚建好的 VMA 树，算出第一条指令在磁盘文件里的精确偏移量。直到这一刻，内核才真正驱动硬盘，把包含这第一条指令的 4KB 数据读入物理内存，建立页表映射，最后让 PC 指针重试执行。
后续循环： 随着程序继续往下跑，只要碰到了没有映射的虚拟地址（无论是新的代码还是数据），就再次触发缺页，循环上述找 VMA 和读盘的过程。

文件类型 核心关注点 排列方式 地址状态
.o 目标文件节（Section）级别仅字节对齐，文件内紧凑无缝均为相对偏移 0x0，带重定位表待回填ELF 可执行文件段（Segment）级别文件内依然紧凑排列，物理页在接壤处复用并双重映射已被链接器分配固定虚拟地址（VA）
elf文件在运行时候采用双重映射，就比如一个内存中105有4字节是只读后面5字节只写，在物理内存紧凑排列的，然后在映射会被映射两次，比如0x80000400 0x80000500 保证4kb对齐映射这个物理页，然后基于不同权限，偏移量虚拟地址固定了，记住虚拟内存不占空间。

所有的相同类A公用一个虚函数表 ，类A开头存放一个指针，指向这个虚函数表地址。虚函数表本质是一个指针数组，当子类重写父亲函数，这张表会重新生成一份。

void task6()
{
    typedef void(*Func)(void *);
    class Base {
    public:
        virtual void sayHello() {
            cout << "Hello from Base!" << endl;
        }
    };
    class Derived : public Base {
    public:
        void sayHello() override {
            cout << "Hello from Derived!" << endl;
        }
    };
    Derived a;
    // 告诉编译器8字节读取
    auto vptr = reinterpret_cast<void**>(&a);
    // *vptr就是地址 强转为void **获取了函数指针数组
    auto vtable = reinterpret_cast<void**>(*vptr);
    auto Test = reinterpret_cast<Func>(vtable[0]);
    cout << "Bypassing C++ syntax to call virtual function directly: " << endl;
    Test(&a);
}
