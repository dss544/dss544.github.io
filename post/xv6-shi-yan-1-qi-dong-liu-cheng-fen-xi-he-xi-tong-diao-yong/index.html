xv6实验[1]-启动流程分析和系统调用

2026-06-06 11 min read

启动流程

1. 汇编入口 entry.S：多核栈初始化

在 xv6 操作系统启动的极早期阶段，系统经历了从汇编入口到 C 语言环境的建立，以及从最高特权级（Machine Mode）到内核级（Supervisor Mode）的巧妙切换。本文将梳理从 entry.S 到跳入 main 函数的核心全过程。

.global _entry
_entry:
        # 1. 将 stack0 数组的基地址加载到栈指针寄存器 sp
        la sp, stack0                   
        # 2. 将常数 4096 (4KB，每个 CPU 的栈大小) 存入 a0
        li a0, 1024*4                   

        # 3. 读取当前正在运行的 CPU 核心编号 (mhartid)
        csrr a1, mhartid           
        # 4. 编号加 1 (如 CPU0 变 1，CPU1 变 2)
        addi a1, a1, 1                 
        
        # 5. a0 = 4096 * (hartid + 1)，计算当前 CPU 栈顶的内存偏移量
        mul a0, a0, a1                
        # 6. sp = stack0 + 偏移量 (例如 CPU0 的 sp 指向 4096，CPU1 指向 8192)
        add sp, sp, a0                

        # 7. 栈准备完毕，正式跳入 start.c 中的 start() 函数
        call start                          
spin:
        # 兜底机制：正常情况不会执行到这里，防止 CPU 跑飞
        j spin

2. start() 函数：特权降级与硬件配置

进入 start() 时，CPU 处于拥有最高权限的 M 模式。为了安全运行内核，系统需要切换到 S 模式。RISC-V 不允许直接降级，因此 start() 巧妙地伪造了一个“中断返回现场”，利用 mret 指令“金蝉脱壳”跳入 S 模式的 main 函数。
在此之前，start 还完成了异常委派、内存权限下放等关键底层配置。

void start() {
  /* 1. 伪造 mstatus：设置“中断前权限”为 S 模式 */
  unsigned long x = r_mstatus();
  x &= ~MSTATUS_MPP_MASK;   // 清除原有的 M 模式标志
  x |= MSTATUS_MPP_S;       // 伪造 S 模式标志
  w_mstatus(x);

  /* 2. 伪造 mepc：设置“中断返回地址”为 main 函数入口 */
  w_mepc((uint64)main);

  /* 3. 内存系统初始化：刚开机时关闭虚拟地址转换，直接使用物理地址 */ 
  w_satp(0);

  /* 4. 异常与中断委派：将大部分软硬件异常下放给 S 模式，避免频繁打扰 M 模式 */
  w_medeleg(0xffff);
  w_mideleg(0xffff);

  /* 5. 使能 S 模式下的外部中断、时钟中断和软件中断 */
  w_sie(r_sie() | SIE_SEIE | SIE_STIE | SIE_SSIE);

  /* 6. PMP 物理内存保护：给 S 模式下放全盘物理内存的 RWX 权限 */
  w_pmpaddr0(0x3fffffffffffffull);
  w_pmpcfg0(0xf);

  /* 7. 初始化系统心跳 (时钟中断) */
  timerinit();

  /* 8. 备份 CPU 编号：将 mhartid 的值存入 tp 寄存器，方便日后 S 模式读取 */
  int id = r_mhartid();
  w_tp(id);

  /* 9. 执行中断返回：CPU 降级至 S 模式，并自动跳转到 mepc 指向的 main 函数 */
  asm volatile("mret");
}

3. timerinit()：配置系统心跳

时钟中断是操作系统的“心脏”，驱动着分时多任务的进程调度。xv6 设置每 0.1 秒触发一次 M 模式下的硬件时钟中断。

void timerinit() {
  /* 获取当前 CPU 编号 */
  int id = r_mhartid();

  /* 设定时间间隔，QEMU 中 1000000 大约对应 0.1 秒 */
  int interval = 1000000; 
  
  /* 更新 CLINT 硬件闹钟：下一次中断时间 = 当前时间 + interval */
  *(uint64*)CLINT_MTIMECMP(id) = *(uint64*)CLINT_MTIME + interval;

  /* 获取 timer_scratch 数组空间，用于中断发生时保存通用寄存器 */
  uint64 *scratch = &timer_scratch[id][0];
  scratch[3] = CLINT_MTIMECMP(id);   // 存入闹钟寄存器地址
  scratch[4] = interval;             // 存入时间间隔
  
  /* 将 scratch 的基地址存入特权寄存器 mscratch，供中断汇编代码使用 */
  w_mscratch((uint64)scratch);

  /* 设置 M 模式的中断向量表基址：中断发生时跳入 timervec 汇编 */
  w_mtvec((uint64)timervec);

  /* 开启 M 模式全局中断与时钟中断 */
  w_mstatus(r_mstatus() | MSTATUS_MIE);
  w_mie(r_mie() | MIE_MTIE);
}

4. timervec：时钟中断

当 0.1 秒的闹钟响起，硬件会强制跳转到 timervec。由于汇编代码干活需要使用通用寄存器，这段代码利用 mscratch 和原子交换指令 csrrw 实现了极度精妙的“空手套白狼”，并在处理完毕后向 S 模式发送软件中断，触发进程调度。

.globl timervec
.align 4
timervec:
        # 1. 原子交换：a0 变成 scratch 的内存指针，原 a0 数据被安全锁入 mscratch
        csrrw a0, mscratch, a0

        # 2. 保护现场：将 a1, a2, a3 的值存入 scratch[0..2] 腾出寄存器
        sd a1, 0(a0)
        sd a2, 8(a0)
        sd a3, 16(a0)

        # 3. 续定闹钟：读取闹钟寄存器物理地址和时间间隔
        ld a1, 24(a0)       # a1 = CLINT_MTIMECMP(hart)
        ld a2, 32(a0)       # a2 = interval (0.1s)
        
        # 计算并写回下一次中断时间 (旧时间 + 0.1s)
        ld a3, 0(a1)
        add a3, a3, a2
        sd a3, 0(a1)        # 硬件自动开始下一次 0.1 秒倒计时

        # 4. 注入软中断：向 sip 寄存器写 2，给 S 模式发送一个软件中断
        # 这将唤醒内核态的中断处理机制，进而触发进程的 yield() 调度
        li a1, 2
        csrw sip, a1

        # 5. 恢复现场：将保存在内存里的 a1, a2, a3 还原
        ld a3, 16(a0)
        ld a2, 8(a0)
        ld a1, 0(a0)

        # 6. 还原 a0：再次交换，恢复被中断程序的 a0 值，mscratch 重新变回内存指针
        csrrw a0, mscratch, a0

        # 7. 中断返回，回到刚才被中断的程序继续执行
        mret

MIT 6.S081 Lab: Syscall 实验记录与核心代码剖析

本次实验的核心目的是深入理解 xv6 操作系统的系统调用机制（System Call），并亲手实现两个新的系统调用：trace（系统调用追踪）和 sysinfo（系统状态信息收集）。

一、 Trace: 系统调用追踪 (Moderate)

trace 的核心需求是实现一个系统调用 trace(mask)。根据传入的掩码（mask），内核需要在后续每次执行相应的系统调用时，打印出追踪信息。

  1. 注册系统调用
    要在 xv6 中新增一个系统调用，需要在内核态与用户态的边界处完成全套注册流程。具体修改点如下：
    kernel/syscall.h：新增系统调用号 #define SYS_trace 22。
    kernel/syscall.c：声明 extern uint64 sys_trace(void);，并在 syscalls 函数指针数组中增加映射 [SYS_trace] sys_trace。
    user/user.h：添加用户态接口声明 int trace(int);。
    user/usys.pl：添加汇编入口跳板 entry("trace");。

  2. 状态保存与继承
    为了让系统调用知道当前进程需要追踪哪些调用，需要在进程控制块（PCB）中增加一个状态记录：
    在kernel/proc.h的struct proc中新增成员变量 int trace_mask;。
    关键点：子进程需要继承父进程的追踪状态。因此在 kernel/proc.c 的 fork() 函数中，拷贝进程状态时需加入：np->trace_mask = p->trace_mask;

  3. 核心逻辑实现
    在kernel/sysproc.c中实现真正的内核处理函数。通过argint获取用户态传入的参数，并保存到当前进程结构体中：

uint64
sys_trace(void)
{
  int mask;
  // 获取第一个参数（掩码）
  if(argint(0, &mask) < 0)
    return -1;
  // 将掩码打上进程烙印
  myproc()->trace_mask = mask;
  return 0;
}

最后，在系统调用的统一入口 syscall()（位于 kernel/syscall.c）中“埋点”。利用位运算 (p->trace_mask >> num) & 1 判断当前系统调用号是否在追踪掩码内：

void
syscall(void)
{
  int num;
  struct proc *p = myproc();
  num = p->trapframe->a7; // a7 寄存器保存着系统调用号
  if(num > 0 && num < NELEM(syscalls) && syscalls[num]) {
    p->trapframe->a0 = syscalls[num](); // 执行真正的系统调用
    // 如果掩码命中，打印追踪信息
    if((p->trace_mask >> num) & 1) {
      // 需自行补充 sys_str 字符串数组以映射调用名称
      printf("%d: syscall %s -> %d\n", p->pid, sys_str[num], p->trapframe->a0);
    }
  } else {
    printf("%d %s: unknown sys call %d\n", p->pid, p->name, num);
    p->trapframe->a0 = -1;
  }
}

二、 Sysinfo: 系统信息收集 (Moderate)

sysinfo 系统调用要求我们统计当前 xv6 系统的两个关键指标：剩余物理内存大小和活跃进程数，并将结果安全地拷贝回用户空间。

1. 统计剩余内存大小 (freemem)

xv6 的物理内存分配器（在 kernel/kalloc.c 中）使用一个单向链表 kmem.freelist 来维护所有的空闲内存页。只需加锁并遍历该链表，将节点数乘以页大小（PGSIZE）即可得出剩余字节数：

uint64 freemem(void)
{
  struct run *r;
  uint64 freeNum = 0;
  acquire(&kmem.lock);
  r = kmem.freelist; // 获取空闲链表头
  while(r) {
    freeNum += PGSIZE; // 每遍历一个节点，增加一页的字节数 (4096)
    r = r->next;       // 游标后移
  }
  release(&kmem.lock);
  return freeNum;
}

2. 统计活跃进程数 (num_proc)

系统的所有进程结构体都预分配在一个全局数组 proc[NPROC] 中（见 kernel/proc.c）。
遍历该数组，只要进程的状态 p->state 不是 UNUSED，就说明该坑位被占用（无论是在运行、睡眠还是就绪状态）：

uint64 num_proc()
{
  uint64 procNum = 0;
  struct proc *p;
  for(p = proc; p < &proc[NPROC]; p++) {
    acquire(&p->lock);
    // 只要不是 UNUSED，就计入活跃进程
    if(p->state != UNUSED) {
      procNum++;
    } 
    release(&p->lock);
  }
  return procNum;
}

3. 跨越边界的数据搬运 (sys_sysinfo)

统计完数据后，需要将其组装进 struct sysinfo 结构体中。
由于内核页表与用户页表不同，内核绝不能直接使用 C 语言指针给用户空间赋值。必须借助 xv6 底层的 copyout 函数，安全地将数据搬运到用户指定的虚拟地址：

#include "kernel/sysinfo.h"
uint64
sys_sysinfo(void)
{
  struct sysinfo info;
  uint64 user_addr;
  struct proc *p = myproc();
  // 1. 获取用户传入的结构体收货地址（指针）
  if (argaddr(0, &user_addr) < 0)
    return -1;
  // 2. 收集系统信息
  extern uint64 freemem();
  extern uint64 num_proc();
  info.freemem = freemem();
  info.nproc = num_proc();
  // 3. 利用 copyout 安全拷贝数据回用户空间
  if(copyout(p->pagetable, user_addr, (char *)&info, sizeof(info)) < 0)
    return -1;
  return 0; // 成功返回 0
}

总结：
本次实验不仅巩固了对 C 语言位操作和链表遍历的基础掌控，更重要的是理清了 RISC-V 架构下内核态与用户态的内存隔离机制。无论是利用 trapframe 传递参数，还是通过 copyout 突破页表壁垒，都展示了底层系统设计的严谨性与巧妙性。
