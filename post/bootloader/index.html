Bootloader

2026-06-14 4 min read

第一步：关闭全局中断 (非常关键)
第二步：反初始化所有开启的外设 (特别是 USB)
第三步：恢复时钟到默认状态
第四步：关闭并清理 SysTick (滴答定时器)
APP 刚一启动还没配好 VTOR，SysTick 中断就来了，直接跑飞
第五步：清除所有 NVIC 挂起的中断,手动设置主栈栈顶地址 MSP

一份标准的 Bootloader 跳转代码模板

typedef void (*pFunction)(void);
pFunction Jump_To_Application;
uint32_t JumpAddress;

#define APP_ADDRESS 0x08010000

void Jump_To_App(void)
{
    // 1. 检查栈顶地址是否合法 (判断是否真的有 APP 存在)
    if (((*(__IO uint32_t*)APP_ADDRESS) & 0x2FFE0000) == 0x20000000)
    {
        // 2. 关全局中断
        __disable_irq();
        
        // 3. 反初始化外设 (解决你 USB 卡死的问题)
        // HAL_PCD_DeInit(&hpcd_USB_FS); 
        // 各种 HAL_UART_DeInit 等...
        
        // 4. 恢复系统时钟到默认态 (切回HSI，关PLL)
        HAL_RCC_DeInit();
        // 5. 关闭 SysTick
        SysTick->CTRL = 0;
        SysTick->LOAD = 0;
        SysTick->VAL  = 0;
        // 6. 清理 NVIC 中断状态
        for (int i = 0; i < 8; i++) {
            NVIC->ICER[i]=0xFFFFFFFF; 
            NVIC->ICPR[i]=0xFFFFFFFF; 
        }
        // 7. 获取 APP 的复位向量地址 (APP_ADDRESS + 4 存放的是 Reset_Handler 地址)
        JumpAddress = *(__IO uint32_t*) (APP_ADDRESS + 4);
        Jump_To_Application = (pFunction) JumpAddress;
        // 8. 设置主栈指针 MSP
        __set_MSP(*(__IO uint32_t*) APP_ADDRESS);
        // 9. 真正执行跳转 (其实就是调用函数指针，修改了 PC 指针)
        Jump_To_Application();
    }
}

  1. 终极内功心法：官方应用笔记 (Application Notes, AN)
    永远不要只看 Datasheet（数据手册）和 Reference Manual（参考手册）。芯片原厂（如 ST、NXP、TI）的资深架构师会专门写一类文档叫 Application Notes（应用笔记）。

精髓所在： 比如针对你今天看到的 ADC 精度问题，ST 有一篇极其经典的实战文档 AN2834《How to get the best ADC accuracy in STM32 microcontrollers》。里面不仅讲了内部参考电压，还极其详尽地剖析了阻抗匹配、运放跟随、PCB 走线干扰以及如何用 DMA 防抖。

获取路径： 去 ST 官网搜你的芯片型号，在 Documentation 栏目下专门筛选 Application Notes。这里面全是原厂老专家几十年的实战经验总结。

  1. 原厂的官方示例源码库 (Projects & Examples)
    你以为 CubeMX 生成出来的代码就是标准答案吗？大错特错。
    在 STM32 的 HAL 库安装目录下（例如 STM32Cube_FW_F4_V1.xx.x），有一个 Projects 文件夹。里面包含了针对官方开发板的各种极端和高级用法代码。比如复杂的 DMA 乒乓缓存、定时器高级联动、双 ADC 同步采样等，原厂都写了极其严谨的标准示范代码放在那里，只是 CubeMX 的图形界面点不出来而已。

  2. 高质量的硬核社区与论坛
    抛弃那些满是“求个源码”的入门级贴吧，去这些地方看一线工程师的实战讨论：

硬汉嵌入式 (Armfly) 论坛： 国内做 STM32、RTOS 底层架构和 DSP 算法极其硬核的社区。他们发布的“高级篇教程”里，全是你今天看到的这种工业级处理手法。

EEVblog (英文社区)： 全球顶级的电子硬件工程师论坛。当你在底层遇到那种解释不通的玄学 BUG 时，用英文在这里搜，大概率能看到国外工程师极其深度的示波器抓轨分析和代码级 Workaround（规避方案）。

RT-Thread 开发者社区： 里面有大量经验丰富的开发者讨论底层驱动的健壮性设计和设备驱动框架。

  1. 工业级/车规级的顶级开源项目
    就像你这次通过看开源项目学到 ADC 校准一样，继续保持这个习惯：

无人机飞控项目 (PX4, ArduPilot)： 这些项目对传感器数据融合、ADC 采样精度、系统实时性的要求极其变态。去翻看它们的底层驱动（HAL）代码，简直是教科书级别的严谨。

优秀的开源协议栈： 除了你已经接触过的 CherryUSB，还可以多看看 lwIP、FatFS 的底层移植接口，看看各路大神是如何把复杂的硬件时序抽象成优雅的软件架构的。
